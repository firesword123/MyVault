# 模块协议与生命周期

## 1. 决策

MyVault 采用“轻主程序 + 独立重模块”架构。

- `myvault.exe` 是主程序：笔记、设置、更新、DataRoot 选择、模块启动器，以及轻量播放列表和唯一的音频播放器。
- DL_ASMR、图库、视频等重功能各自是独立的可执行程序和独立窗口。
- 模块打开时才启动；模块窗口关闭即退出进程并释放其 WebView2、GPU、媒体解码器和文件缓存。
- `aria2c`、`7z`、`ffmpeg` 等为无界面工具进程，只由所属模块按任务启动；任务结束必须退出。

主程序不嵌入、不预加载、不保留任何重模块页面。主程序只在用户明确播放时保留当前音频、播放队列和一个解码器；封面网格、作品浏览器和图库资源不进入主 WebView。

### DL_ASMR 的折衷边界

- `myvault-dl-asmr.exe` 是仅面向 RJ 编号 DLsite 作品的浏览器，负责导入、检索、元数据、封面和文件夹浏览。
- 用户点击音频时，DL_ASMR 通过会话管道把当前文件夹的有界播放队列发送给主程序。
- 主程序在笔记 WebView 内按需挂载播放器侧栏；侧栏持有唯一 `<audio>`、队列、上一首/下一首、暂停和音量，不创建第二个播放器窗口。
- DL_ASMR 窗口关闭后其进程与 WebView2 进程树退出，但主程序播放器继续播放。
- 主程序退出、用户关闭播放器侧栏或清空队列时停止音频并释放媒体源。
- 图库与这套持久播放器无关。图库由独立的 `myvault-gallery.exe` 承载，并在关闭窗口时完整退出。

### 拼接 UI 的定义

“拼接 UI”仅指模块与主程序共享标题栏、主题令牌、字体、间距、图标和交互规范，呈现为同一产品。

不同进程不共享 React DOM，也不在主窗口内嵌模块页面。模块始终拥有自己的原生窗口和自己的 WebView2。

### 1.1 可吸附扩展窗口（后续能力）

未来的“背包扩展 UI”按可吸附扩展窗口设计。典型入口是在笔记页点击某个扩展，先打开靠近当前笔记窗口的小型侧栏，再按用户操作展开为详情页。

这仍然是独立原生窗口，而不是主窗口内部的侧栏组件。吸附表示两个窗口在位置、尺寸、层级和主题上协同，不表示共享 React DOM 或 WebView2。

扩展窗口至少具有三种展示状态：

| 状态 | 含义 | 窗口行为 |
| --- | --- | --- |
| `detached` | 独立浮动 | 可自由移动、调整尺寸，不跟随主窗口 |
| `docked-compact` | 吸附侧栏 | 吸附在宿主笔记窗口左侧或右侧，跟随移动、最小化、恢复和 DPI 变化 |
| `expanded-detail` | 展开详情 | 保留独立进程与窗口，可扩大为完整详情页；允许继续吸附或转为浮动 |

交互与生命周期约束：

- 默认吸附最近触发扩展的笔记窗口；左右侧由可用屏幕空间和用户上次选择决定。
- 接近宿主窗口边缘的吸附阈值、侧栏宽度和展开宽度属于共享 UI 规范，不由各模块自行猜测。
- 吸附时仅相对宿主维护层级，不使用全局置顶；宿主失去焦点后扩展不得遮挡其他应用。
- 拖离吸附区域即转为 `detached`，不重建 WebView，不丢失选中项、滚动位置或未提交编辑。
- 宿主移动、缩放、最小化、恢复、跨显示器或 DPI 改变时，主程序发送新的宿主边界；扩展窗口重新计算位置并限制在工作区内。
- 宿主关闭时，临时扩展默认关闭；声明可独立存在的扩展可转为 `detached`。无论哪种行为都必须由能力协商明确，禁止留下隐藏窗口。
- 小型侧栏只加载紧凑视图需要的数据；原图、媒体解码器或完整详情资源必须等到显式预览或展开后再创建。
- 扩展仍遵守模块数据域权限。笔记上下文由主程序通过 `open.target` 或后续状态消息明确提供，扩展不得自行扫描笔记目录。

协议预留以下能力与消息语义，实际字段在实现侧栏时冻结：

- 能力：`dock`, `detach`, `compactView`, `detailView`, `followHostBounds`。
- 主程序命令：`attach`、`detach`、`setViewMode`、`hostBoundsChanged`。
- 模块状态：当前展示状态、吸附边、窗口边界、能否脱离宿主继续存在。

本次 DL_ASMR 迁移不实现可吸附扩展窗口。播放器采用主笔记窗口内嵌侧栏，作为资源占用与窗口稳定性的折衷；未来“背包扩展 UI”仍按上述独立可吸附窗口协议另行实现和验证。

## 2. 可执行程序与职责

| 程序 | 窗口 | 数据写权限 | 常驻条件 |
| --- | --- | --- | --- |
| `myvault.exe` | 主笔记窗口（含按需播放器侧栏） | 笔记、全局设置、模块注册表；播放器队列仅驻留内存 | 用户打开 MyVault 时；播放器组件按需挂载和卸载 |
| `myvault-dl-asmr.exe` | DL_ASMR 窗口 | `DL_ASMR/` 数据域 | DL_ASMR 窗口存在时 |
| `myvault-gallery.exe` | 图库窗口 | `Gallery/` 数据域 | 图库窗口存在时 |
| `myvault-video.exe` | 视频窗口 | `video/` 数据域 | 视频窗口存在时 |
| 工具程序 | 无 | 仅任务输出目录 | 单个任务执行期间 |

一个 Vault 内，同类模块最多运行一个实例。再次打开时，主程序向现有实例发送激活命令，不创建第二个窗口。

## 3. 启动与 IPC

### 3.1 启动参数

主程序只能以参数数组启动经白名单登记的模块，不得拼接 shell 命令。

```text
myvault-dl-asmr.exe --data-root <绝对路径> --module dl_asmr --session <UUID> --parent-pid <PID> --pipe <管道名>
```

- `data-root`：主程序已解析、已迁移且通过 `Manifest.json` 验证的 `MyVaultData` 绝对路径。
- `module`：固定模块标识；必须与可执行程序登记值相同。
- `session`：每次启动生成的 UUID，用于拒绝陈旧连接。
- `parent-pid`：主程序 PID，仅用于健康检查。
- `pipe`：本次会话专用 Windows 命名管道，格式为 `\\.\pipe\myvault-<session>`。

模块在启动后 10 秒内连接管道并发送 `hello`；超时或版本不兼容时，主程序终止该模块并显示启动失败。

### 3.2 消息格式

管道使用 UTF-8 JSON，单条消息以 4 字节小端无符号长度前缀分帧；最大长度 1 MiB。每条消息必须包含：

```json
{
  "version": 1,
  "session": "UUID",
  "type": "hello | ready | open | focus | player.replace_queue | shutdown | state | error",
  "requestId": "UUID"
}
```

消息类型与必填字段：

| 类型 | 发送方 | 额外字段 | 含义 |
| --- | --- | --- | --- |
| `hello` | 模块 | `module`, `moduleVersion`, `pid` | 身份和版本声明 |
| `ready` | 模块 | `capabilities` | 已可接收命令 |
| `open` | 主程序 | `target` | 打开模块内的指定资源；无目标则显示首页 |
| `focus` | 主程序 | 无 | 恢复、置顶并聚焦已有窗口 |
| `player.replace_queue` | DL_ASMR | `payload.source`, `payload.startIndex`, `payload.tracks` | 用 DL_ASMR 当前文件夹的音频替换主程序播放队列并立即播放选中项 |
| `state` | 模块 | `status` | 可选状态更新，仅用于主程序显示 |
| `shutdown` | 主程序 | `reason` | 请求正常退出 |
| `error` | 任一方 | `code`, `message` | 可向用户显示的失败信息 |

`hello` 的 `version`、`session`、`module` 任一不匹配即断开连接并退出。未知消息类型直接返回 `error`，不执行任何动作。

## 4. 生命周期

1. 用户在主程序选择模块。
2. 主程序查找该 Vault 的既有模块实例；存在则发送 `open` 和 `focus`，结束本次启动流程。
3. 不存在则创建会话管道，启动模块并等待 `hello`、`ready`，随后发送初始 `open`。
4. 模块只在收到 `ready` 前初始化自身 UI；不在启动时扫描其他模块数据或启动工具程序。
5. 用户关闭模块窗口时，模块关闭文件句柄并退出自身进程；已经交给主程序的音频队列继续播放。
6. 用户退出主程序时，主程序向全部模块发送 `shutdown`，最多等待 5 秒；未退出的模块由主程序终止。
7. 模块发现管道断开或 `parent-pid` 不存在时，立即停止工具子进程并在 5 秒内自行退出。

主程序启动的模块及其工具子进程必须置于同一个 Windows Job Object，并启用 `KILL_ON_JOB_CLOSE`。这保证主程序崩溃或被强制结束后没有孤儿模块进程。

模块不允许在关闭后转入托盘、后台服务或隐藏窗口。播放持续发生在仍存活的主程序中，不属于 DL_ASMR 模块后台驻留。需要持久的下载、索引或转码任务必须另行设计为服务，不能借“模块关闭”继续运行。

## 5. 数据所有权与兼容性

- 主程序是 Vault 路径和全局设置的唯一写入者。
- 每个模块只写自己的数据域；模块不得直接修改其他模块的数据、全局设置或笔记文件。
- 模块可读取主程序通过启动参数或 IPC 明确提供的数据；不得自行猜测其他数据目录。
- DL_ASMR 只向主播放器传递有界的曲目元数据和 `MyVaultData` 内绝对文件路径；不传递媒体字节、封面位图、DOM 或 React 状态。
- 主播放器的队列属于临时运行状态，不取得 DL_ASMR 索引写权限。播放进度持久化如需增加，应通过协议回写给 DL_ASMR 数据域所有者。
- 所有持久化写入使用“临时文件 + 原子重命名”；索引或元数据不得原地部分覆盖。
- 每个数据域根目录包含 `schemaVersion`。迁移由所属模块执行，并在成功完成后才写入新版本号。
- 主程序与模块的发布版本必须完全一致。主程序更新时将全部模块作为同一更新单元下载、校验、替换；禁止半更新状态启动。

模块的 WebView2 数据目录必须独立，例如 `AppData/.../webview/dl_asmr`。主程序不得与模块共享浏览器缓存或 profile。

## 6. UI 与资源规则

- 共享的设计令牌和基础 UI 组件位于 `src/` 的公共组件与样式中；三个前端入口通过同一次 Vite 构建复用它们，不通过运行时注入或复制粘贴保持一致。
- 每个模块拥有自己的标题栏、导航和内容区；主程序只负责启动入口与状态提示。
- 图库只显示生成后的缩略图，必须分页；原图仅在显式预览时加载。
- 音频只在用户明确播放时由主程序创建一个解码资源；关闭 DL_ASMR 浏览器不停止主播放器。清空队列或退出主程序时必须执行 `pause`、移除 `src` 并重新 `load` 以释放媒体源。
- 任何模块不得缓存其他模块的页面实例、DOM、媒体 URL、位图或 GPU 纹理。
- 设置页显示的资源用量必须按模块进程树汇总，不得只显示 Rust 主进程。

## 7. 安全与发布

- 所有模块和工具程序均随安装包发布并签名；不从任意目录执行同名程序。
- 启动白名单包含固定可执行文件名和允许的参数形状；文件路径参数必须在解析后验证其归属范围。
- 工具程序的版本、来源、许可证和 SHA-256 记录在发布清单中。
- 工具输出只能写入所属模块的临时目录或数据域，完成后由模块原子移动到正式位置。

## 8. 验收标准

模块化改造完成的判定条件：

1. 启动主程序后，不存在任何 DL_ASMR、Gallery、视频模块或工具进程。
2. 打开一个模块后，仅该模块及其必要 WebView2 子进程出现。
3. 关闭 DL_ASMR 后 10 秒内，DL_ASMR 及其 WebView2 子进程全部退出；已经交给主程序的音频继续播放，且不存在第二个音频解码器。
4. 重复打开同类模块只聚焦已有实例，不产生第二个实例。
5. 主程序异常结束后 10 秒内不存在孤儿模块或工具进程。
6. 模块升级、数据迁移失败或 IPC 版本不匹配时，不破坏原有 Vault 数据且给出可读错误。
7. 主笔记窗口在从未播放音频时不加载任何媒体文件；播放器侧栏不加载 DL_ASMR 浏览器代码、封面或索引。关闭侧栏后组件卸载、队列清空、媒体源移除，不得留下隐藏播放器或第二个 WebView。

## 9. 当前实现状态

模块启动器、命名管道协议、进程注册表、Job Object 管理、DL_ASMR sidecar 和 Gallery sidecar 均已实现。视频模块与可吸附扩展窗口仍是后续能力。

## 10. 当前模块边界

DL_ASMR 已完成独立进程迁移，并保持作品浏览能力与主程序播放器的生命周期分离：

- 主程序不再挂载 DL_ASMR React 页面，也不注册 DL_ASMR 数据命令。
- 点击主程序的 DL_ASMR 入口时启动 `myvault-dl-asmr.exe`；已存在实例时仅发送 `open`、`focus`。
- DL_ASMR 使用自己的 WebView2 数据目录，关闭窗口即退出模块进程。
- 主程序和 DL_ASMR 使用版本、会话与进程身份校验后的命名管道通信。
- DL_ASMR 进程加入主程序的 Windows Job Object；主程序退出或崩溃时由系统清理模块进程树。
- DL_ASMR 页面不再持有 `<audio>`、播放器面板或字幕播放状态；点击音频发送 `player.replace_queue`。
- 主程序在笔记布局右侧按需挂载播放器侧栏并持有唯一 `<audio>`；DL_ASMR 关闭后，只要侧栏仍开启，播放就继续。
- 顶栏“播放器”是侧栏开关：首次点击挂载，再次点击卸载、清空队列并释放媒体源。

Gallery 使用同一套模块协议与生命周期约束，负责分页缩略图、显式原图预览和导入；它不与主程序共享媒体状态。可吸附扩展窗口、展开详情设计以及视频模块尚未实现。
